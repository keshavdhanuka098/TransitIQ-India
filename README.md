# TransitIQ India 🇮🇳
### Smarter Routes. Better Cities.

A premium, production-quality **frontend-only** dashboard for a Smart Public Transport & Bus Optimization System, focused on Indian cities.

This is a real Vite + React + TypeScript application (not a static mockup) — every page, chart, map, and interaction is fully wired to a realistic local mock dataset, structured so a real backend can be swapped in later with minimal changes.

## Tech stack

- React 19 + Vite + TypeScript
- Tailwind CSS v4
- Framer Motion (animations, page/modal transitions)
- Recharts (all charts)
- Leaflet + React-Leaflet (live network map, OpenStreetMap/CARTO tiles — no Google Maps)
- Lucide React (icons)
- React Router (client-side routing)

## Getting started

```bash
npm install
npm run dev
```

Then open the printed local URL (typically `http://localhost:5173`).

To build for production:

```bash
npm run build
npm run preview
```

## What's included

- **Loading screen** — animated logo, route-draw, travelling bus marker, then fades into the dashboard (~1.6s)
- **Overview** — hero header, city selector (7+ Indian cities), 6 animated KPI cards with sparklines and trend indicators, recent alerts
- **Live Network** — Leaflet map with animated bus markers, route lines colored by congestion, stops, click-to-inspect bus info panel, and a live vehicle feed list. Bus positions gently drift every few seconds to simulate real-time movement.
- **Route Explorer** — from/to search across real stop names, animated route cards
- **Route Details** — animated horizontal stop timeline, per-route mini-map, 14-day performance chart, list of buses currently on the route
- **Fleet Management** — fleet-wide stats, searchable/paginated table, slide-in bus detail drawer with a historical performance chart
- **Analytics** — 6 chart types: passenger volume (line), route performance (bar), 30-day delay trend (line), demand by hour (area), fleet utilization (donut), city comparison (horizontal bar)
- **Optimization Center** — network efficiency stats, route optimization table (demand vs. capacity, with recommendations), an interactive **What-if Simulator** (bus count, peak frequency, fleet allocation slider → live-recalculated waiting time / capacity / congestion / utilization / cost), a demand heatmap switchable by time of day, and a full city comparison table
- **Global search** across bus numbers, routes, and stops
- **Dark / light theme**, persisted to `localStorage`
- Loading / empty / error states on every major data view
- Fully responsive: mobile bottom nav, mobile drawer nav, stacked layouts

## Data

All mock data lives in `src/data/*.json` and is generated by `scripts/generate-data.mjs` (seeded, so it's stable across runs). It currently contains:

- 8 cities, 128 stops, 186 routes, ~1,130 buses, 60 alerts

`src/data/mockApi.ts` wraps this JSON in `async` functions that mimic a real API's shape (returning Promises with small artificial delays). **To connect a real backend**, replace the function bodies in `mockApi.ts` with actual `fetch`/HTTP calls — no component code needs to change, since every page already calls these functions and handles loading/empty/error states.

## Project structure

```
src/
  components/
    layout/       Navbar, Footer, LoadingScreen, mobile nav, search, notifications
    dashboard/     StatCard, CitySelector
    map/           Leaflet map, bus info panel, live feed list
    routes/        Route cards, stop timeline
    fleet/         Bus detail drawer
    charts/        Chart card wrapper
    optimization/  Optimization table, simulator, heatmap, city comparison
    ui/            Logo, AnimatedNumber, StatusBadge, loading/empty/error states
  context/         Theme + City React contexts
  data/            Mock JSON datasets + mockApi.ts data-access layer
  pages/           Overview, LiveNetwork, RouteExplorer, RouteDetails, Fleet, Analytics, Optimization, NotFound
  types/           Shared TypeScript interfaces
scripts/
  generate-data.mjs  Dataset generator (re-run with `node scripts/generate-data.mjs`)
```

## Notes

- The favicon and all logo placements use the same brand mark (`src/components/ui/Logo.tsx` / `public/favicon.svg`).
- Colors reference India subtly (a muted saffron accent alongside deep green and blue) rather than a literal tricolor theme.
- No backend, auth, database, or payment code is included by design — this is a frontend demonstration layer only.
